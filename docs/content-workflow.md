# 字幕与路线事件

## 单一成稿

前端只显示 `public/data/route-*.subtitles.json` 中的教学字幕，优先使用 `correctedText`，未修改的条目使用 `rawText`。不提供 ASR/OCR 切换、原文对照或校对状态，避免学员混淆。当前成稿以 ASR 为主，OCR 只作辅助；五号线另补入三条 ASR 漏掉的清晰讲解。

`content/subtitles/route-*.srt` 是同一成稿的标准 SRT 导出，保留毫秒时间。ASR 分句不重新猜测边界；OCR 补段保留自己的显示时间。文字校对不代表实际考试指令或动作窗口已核实。

## 来源与人工修订

- `raw/asr/route-*.srt`：原始 ASR 素材，Git 忽略，不修改。需使用未经裁剪或变速的同一段原始视频转写。
- `content/subtitle-sources/route-*.asr.json`：可提交的 ASR 原文快照，包含源文件名、原文及毫秒时间。
- `public/data/route-*.ocr.json`：已有 OCR 原文快照，保留乱码和识别失败提示，不直接编辑。
- `content/subtitle-reviews/route-*.json`：人工维护的文字修订、OCR 补段、修改理由、跨路线来源引用及重点疑点。
- `docs/subtitle-review.md`：自动生成的修订报告、重点回看项和候选口令时间索引。

```sh
pnpm import:asr          # 读取 raw/asr，保留原文快照
pnpm import:ocr          # 仅原始 OCR 有变化时运行
pnpm prepare:subtitles   # 生成前端 JSON、成稿 SRT 和校对记录
pnpm test
pnpm build              # 构建前也会重新生成成稿
```

原文与校正文分别存储。修订包含 `expectedRawText`，来源变化时停止生成，不能默默把旧修改应用到另一句；所有来源引用必须存在，重复修订或与 ASR 重叠的 OCR 补段会报错。修改后重新执行生成命令，再启动/刷新前端；不要直接修改生成文件。

ASR/OCR 允许一对多、多对一，字幕显示与声音时间可能存在小偏差。当前仅做文字和时间上下文对照，没有把两源逐条等同，也没有自动套用 OCR 文本。无法辨认的 OCR 不补入学员字幕。报告中的无 ASR 时间覆盖条目只是诊断信息，可能是无声提示、乱码或漏识别，仍需回看视频。

## 复核状态

成稿的 `reviewScope` 为 `text-only`。`text-reviewed` 表示已进行文字层面的审阅，不等于听音或画面核实；`needs-review` 用于显式疑点，以及涉及操作、方向、数值或规则的内容。含操作信息的字幕保留作者原意，不自动将其变为规则。推断补字及两源冲突须记录理由，不标记为已核实。

校对元数据供维护者使用，不在学习界面逐条展示。学员看到的是一份连续字幕；维护者通过校对报告与来源快照继续复核。

## 考试事件

字幕与考试事件分开存储。`trainingEventSchema` 预留指令时间、动作窗口、项目类型、方向、来源字幕 ID、复核状态和提示。还需要明确步骤要求、训练限时与评分规则，才能构建正式训练引擎。

报告里的独立口令形式只是候选定位，ASR 未区分考试播报与教练复述。至少区分考试指令、教练预告、事后解释、实际动作和临时交通情景；字幕时间不能直接变成操作触发时间，旧 DEMO 的人工推测节点不迁移。

仅核实的事件可进入正式模拟。视频播放时间决定路线位置，操作计时独立管理；暂停、缓冲、拖动、变速、页面隐藏及重练的计时和重置行为应另行定义。灯光和上车准备作为独立模块，不虚构成当前影片中的片段。
