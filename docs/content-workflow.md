# 字幕与路线事件

## ASR 素材约定

尽量使用与当前 OCR 相同的原始 MP4 做转写，不裁剪片头、不删停顿、不做变速，以便共用时间基准。建议保留完整原文并导出带时间戳的 SRT；可同时保存转写服务提供的 JSON，便于保留更细粒度时间信息。文件可放在 `raw/asr/route-5.srt`、`route-6.srt`、`route-7.srt`。这只是约定，当前尚未实现 ASR 导入与自动对齐。

ASR 可能包括教练讲解、考试口令及环境声；OCR 可能包括无声的画面提示。两者不要求逐条对应，也不能仅凭文字相同就认定是同一个事件。对照时应允许一对多、多对一及仅有单侧来源的段落。

## 原文与校正

`public/data/route-*.ocr.json` 来自 `pnpm import:ocr`，保留 UTF-8 原始 SRT 文本、毫秒时间、源文件名和来源类型；当前全部 `unreviewed`，`correctedText: null`。这是自动生成的原始记录，请勿在此直接修订（重新导入会覆盖）。后续校正应另存人工整理文件，包含修改理由和来源引用。

`source` 区分 `ocr` 与 `asr`。人工修正不能覆盖 `rawText`。方向、数值、规则及缺失整句不能凭语境补成已核实内容。两源冲突时回看视频和原声，仍不确定则保留 `needs-review`。

## 考试事件

字幕与考试事件分开存储。`trainingEventSchema` 预留指令时间、动作窗口、项目类型、方向、来源字幕 ID、复核状态和提示。后续还需要明确步骤要求、训练限时与评分规则，才能构建正式训练引擎。

仅核实的事件可进入正式模拟。至少区分考试指令、教练预告、事后解释、实际动作和临时交通情景。字幕显示时间是候选定位，不能直接作为动作触发时间。旧 DEMO 中的人工推测时间不自动迁移。

视频播放时间决定路线位置；实际操作计时独立管理。暂停、缓冲、拖动、变速、页面隐藏及重练时必须明确计时和事件重置行为。灯光与上车准备作为独立模块，不虚构成当前影片中的真实片段。
