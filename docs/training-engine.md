# 暂停练习引擎

路线页支持观看视频、全程练习和单项练习。五、六、七号线分别使用 22、18、22 项已发布的暂停练习节点。它们只经过抽样画面定位，仍保留 `audioStatus: asr-only`、`ruleStatus: unverified`，不参与考试评分。

## 分工和入口

- `src/features/content/queries.ts`：通过 TanStack Query 加载事件文件，经 Zod 校验，拒绝其他路线、未通过画面定位的节点及非空 `examEvents`。
- `src/features/training/engine.ts`：纯状态转换，接收媒体位置、操作和单调时钟时间，不依赖 DOM 或 React。
- `controller.ts`：衔接视频播放、暂停、定位及媒体事件，区分引擎定位与学员拖动。可使用替代媒体对象进行测试。
- `use-training.ts`：订阅引擎快照，绑定媒体、页面可见性事件和计时刷新；切换路线或卸载时取消监听、定时器及播放请求。
- `training-panel.tsx`：复用 shadcn Button、Badge，展示当前步骤、文字反馈、车辆状态和项目列表；完整步骤在播放器侧展示，项目列表放入 Sheet。
- `practice-events.ts`：保留来源事件，单独携带本机 `manualPauseMs`，通过 `pauseTimeMs()` 读取实际暂停点。
- `manual-calibration.ts` / `use-manual-calibration.ts`：校验、读取和保存本机人工时间；`calibration-panel.tsx` 提供视频对照编辑、备份与恢复。

页面通过 `Promise.all` 并行预加载字幕和事件。事件源数据、指纹、候选覆盖检查与生成流程不作改动，未通过定位复核的六号线返回大学路右转仍被排除。

## 会话和项目状态

默认进入路线后观看视频，不触发操作项目。点击“开始全程练习”，从当前视频位置向后练习；之前未练习的节点标记为跳过。需要从头开始时先将视频拖至开头。节点列表也可以直接开始某个项目。

练习经历 `road → practice → review → road/finished`：

1. 正常向前播放越过暂停点时，触发最早的一个未处理节点；暂停视频并定位回该节点，避免 `timeupdate` 的采样间隔导致画面越过太远。
2. `practice` 中按当前教学步骤操作，错误操作提示原因并增加纠正次数，不扣分、不淘汰，没有操作超时失败。
3. 完成后进入 `review`，保留用时、纠正次数和车辆状态，不自动播放。点击“继续路线”再行驶；单项模式点击后结束本项。
4. 路线末项完成或视频自然结束后结束本次练习。跳过不会算完成。

`progress` 描述当前路线位置上的完成/跳过状态，`attempts` 记录本次会话的已完成或已中止尝试，两者不同。刷新、离开路线或重新开始全程练习会建立新会话，目前不持久化训练记录，原有学习设置仍保存在本机。

## 教学步骤与车辆状态

此处的顺序和等待是独立的教学策略，不升级校准数据的考规状态。默认打灯等待为 3000ms，通过 `DEFAULT_SIGNAL_WAIT_MS` 和引擎构造参数配置，不从视频动作区间推导限时。

| 项目 | 教学操作 |
| --- | --- |
| 减速 | 观察前方 → 踩刹车 → 确认继续 |
| 停车瞭望 | 踩刹车 → 确认停稳 → 观察左右 → 确认安全 |
| 直线 | 观察前方 → 确认保持直线；不评价方向盘稳定性 |
| 变道 | 对应方向打灯 → 观察后方 → 等待 → 确认变道 → 关灯 |
| 转弯、掉头 | 对应方向打灯 → 观察后方 → 减速 → 等待 → 确认动作 → 关灯 |
| 超车 | 左灯、观察、等待、驶出、关灯 → 右灯、观察、重新等待、返回、关灯 |
| 靠边停车 | 右灯、观察、减速、等待、确认停车、关灯 → P 挡 → 驻车制动 |

这些步骤不模拟车速、距离、方向盘、真实观察结果，也不添加倒车、熄火或车门动作。停车收尾仍需独立规则复核。

车辆状态包括转向灯及开启时刻、观察方向、制动、行驶/停稳、D/P 挡、驻车制动、原车道/超车道。车辆未停稳时不能挂 P 挡或拉驻车制动。重复点击同一盏已开启的灯不会重置等待；提前关灯或改方向会清除本段观察和等待，回到本段打灯步骤。超车返回的等待单独计时。

每项是独立的动作练习，开始时从 D 挡、驻车制动松开、灯光关闭、行驶状态初始化；上项的观察、制动和等待不沿用。它不是连续车辆动力学模型，路段间视频继续播放前会恢复上述教学初始状态。灯光考试、上车准备仍需独立内容。

## 媒体与时钟行为

使用视频 `currentTime` 决定路线位置，使用 `performance.now()` 的相邻差值累计操作时间。页面每 100ms 刷新展示，但操作到达时会先按其时间戳结算，不依靠定时器次数或视频帧率计时。

| 情况 | 视频与项目 | 操作计时 |
| --- | --- | --- |
| 正常播放 | 按视频位置检测暂停点，仅正常向前播放触发 | 路段播放不累计操作时间 |
| 项目自动暂停视频 | 保留画面，开启操作步骤；正常的 `pause` 事件不算用户暂停 | 继续累计，转向灯等待生效 |
| 用户暂停练习 | 保留步骤与车辆状态，禁用操作；由用户继续 | 冻结，继续后接着累计 |
| 实际缓冲 `waiting` | 等待 `playing` / `canplay`；缓冲时不触发节点 | 冻结；`stalled` 仅在 `readyState < 3` 且视频在播放时阻塞，已有可播放缓冲的下载停顿不阻塞 |
| 变速 | 只影响路段视频速度，仍以媒体位置触发 | 等待和操作时间不乘播放倍速 |
| 拖动、后退 10 秒、外部定位 | 暂停视频，中止当前未完成尝试，清空其步骤、观察、灯光和计时；定位后手动播放。目标之前未完成节点标记为跳过；目标及之后节点重新开放，已完成的历史尝试仍保留 | 定位期间不计时，后续节点重新计时 |
| 引擎自动校正画面位置 | 标记为内部定位，不当作学员拖动，不中止项目 | 定位完成前冻结，`seeked` 后恢复 |
| 页面隐藏 | 暂停视频、禁用操作；回来后仍保持用户暂停，需手动继续 | 隐藏与等待用户继续的时间不累计 |
| 打开路线图 | 暂停视频、禁用操作；关闭后手动继续。完成页也可继续原路线 | 冻结，关闭弹窗不会自行恢复 |
| 视频错误 | 暂停并阻塞，重新加载成功后用户继续 | 冻结 |
| 完成结果、视频结束 | 保留完成/跳过状态，允许选择重练 | 不再累计 |

暂停原因以集合保存，可同时包含手动暂停、缓冲、隐藏、路线图、媒体错误；解除一个原因不会解除其他原因。暂停或离开页面会使未完成的异步播放请求失效，避免迟到的播放结果恢复后台视频。

## 单项重练和回看

- “重练本项”回到本项暂停点，清除本次完成标记和临时车辆状态，操作时间从零开始。尚未完成的尝试记为中止，历史记录保留。
- 在全程练习中重练当前项目，仍保留全程模式，完成后继续后续路线。
- 从项目列表选择单项，进入独立模式，只练所选项目，不自动进入其他节点。
- “回看本项”回到暂停点前 5 秒并保持暂停；点击播放观看，到本项暂停点重新操作。前面的其他节点不会抢占单项练习。

## 人工校准与倍速

播放器和默认设置共用六档速度：0.75、1、1.25、1.5、1.75、2 倍。它只改变视频前进速度，转向灯等待仍按真实有效操作时间累计。

点击路线页“人工校准”结束当前练习并暂停视频。面板默认选中当前练习项目，未在练习时选择离画面最近的项目。视频可继续播放、拖动，或通过 0.1/1 秒按钮微调；校准期间不触发训练。选择其他项目会跳到其有效时间，也可回看暂停点前 5 秒。

“使用当前画面时间”只填入草稿，点击“保存本项”后生效。输入支持 `分:秒.毫秒` 或十进制秒数，内部保存为整数毫秒。时间可超出原 AI 动作区间，但需非负、早于实际视频结尾、晚于前项并早于后项，不允许同刻多个项目；冲突时明确提示，不自动改序。

人工暂停点单独保存在 `roadtest.practice-calibration.v1.<routeId>`，默认事件及其动作区间、证据、来源指纹和复核状态保持不变，不直接修改 `public/data` 生成文件。只允许调整已发布的暂停练习项目，不能借此加入排除项或考试评分事件。

记录包括版本、路线、视频/字幕 SHA-256、保存时视频时长，以及每个已改项目的原始暂停点、原始区间和人工暂停点。加载和导入经过 Zod 校验，再核对来源及顺序；视频/字幕指纹或对应节点默认时间变化时，旧记录不应用、不自动删除，界面提示重新校准。载入视频后还会按实际时长校验，越界时使用默认时间。

有效时间通过 `pauseTimeMs()` 统一进入项目触发、内部定位、单项重练、前 5 秒回看、拖动跳过判断与列表展示。保存会重新建立播放器的引擎会话；结束校准后手动开始练习，未完成尝试不会沿用旧时间继续。

“恢复本项默认”移除该项覆盖，同样检查相邻顺序；“恢复本路线全部默认”需在 Dialog 中确认。备份导出为 JSON，导入仅接受当前路线及相同来源，整体替换本路线人工时间，不影响其他路线。浏览器拒绝保存时仍在本次使用中生效，并提示导出；刷新前需备份，导入可恢复。

## 验证

`pnpm test` 覆盖三条路线所有发布项目、完整路线衔接、错误顺序、灯光重计时、超车双阶段、停车状态保护、媒体定位、重练、交叠暂停原因、后台恢复、播放失败及数据加载边界；人工校准另覆盖新时间实际触发与定位、原始数据不变、时间输入、项目顺序、边界、来源变更、受阻项目排除、本机存储和恢复。`pnpm build` 执行内容生成、生产构建和 TypeScript 检查。

媒体控制测试使用可控时钟和替代视频对象，不能替代真实浏览器验证。应在可用的浏览器中补查视频事件顺序、桌面/手机布局、键盘焦点、路线图与播放速度浮层，以及后台恢复。
